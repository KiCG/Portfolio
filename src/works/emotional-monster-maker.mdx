### 1. プロジェクト概要（Overview）
**タイトル:** Emotional Monster Maker  
**テーマ:** インクルーシブな遊びの提案  
**ミッション:**「感情」を伝えることや表現することが苦手な子供でも、簡単な入力だけで感情をモンスターとして可視化・可触化できるようにする。また、モンスターを生成することを通じて、自己の内面の理解や、他者への自己表現を行う体験を提供する。

### 2. リサーチと洞察（Research & Insight）
本プロジェクトは、私が所属する研究室の「インクルーシブな遊びの提案」という研究テーマからスタートしました。障害の有無や文化的な背景に関わらず、全ての子供が楽しめる遊びを提案するために、太陽が丘公園で**ミラスタ！つながる"こうえん"プロジェクト**  様が開催しているインクルーシブDayでのフィールドリサーチを2回ほど実施しました。インクルーシブDayでは、あそびサポーターとして参加し、保護者の方にアンケートを取ったり、作成した遊びを持っていき、子供からのフィードバックを直接受け取るなど、生の声・体験を元にリサーチを続けていきました。また、研究室のメンバー5人でフィールドリサーチから得られた知見などの共有は行いましたが、各自が独立した遊びの提案をする必要がありました。

#### 2.2 インクルーシブDay3rd 2025.11/01(土)
2回目のフィールドリサーチは、インクルーシブDay3rdで行いました。2回目のリサーチでは実際に作成した遊びを持っていき、子供からのフィードバックを得ることを目的としました。私が作成した遊びは、mocopiを用いてトラッキングされた映像をスクリーンに映すというものでした。インクルーシブDay2ndでのリサーチにより、子どもはシャボン玉などの、自身の行動が視覚的フィードバックとして現れる遊びを好んでいることが分かりました。そのため、子供にmocopiを装着してもらい、自身の動きと連動してスクリーン上の3Dモデルが変化するといった遊びを提案しました。しかし、これはいくつかの問題により失敗します。1つはmocopiの使い方を子供に説明することが難しい点です。mocopiはリアルタイムトラッキングを可能にする、手足に装着するためのデバイスですが、子供たちにはその概念が分からないため、使い方を説明することが困難でした。また、キャリブレーションをある程度の頻度で行う必要があり、これも困難な理由でした。2つ目の理由として、物理的な要因によりスクリーンに投影することが難しかったことが挙げられます。暗闇の空間を作るのが困難なため、テントの中にスクリーンとプロジェクターを配置する必要がありました。テントの中は完全な遮光になっているわけではなく、スクリーンはかなり見づらい状況となっていました。また、プロジェクターもテントの中に配置する必要があり、スクリーンとプロジェクターの間に立たないように意識する必要があるなど、多くの物理的な制約に悩まされました。

#### 2.3 リサーチ結果と考察   
2回のフィールドリサーチの結果、公園に訪れている子供の多くは活発、積極的といった属性を持っていることが観察されました。反対に、それらの属性を持たないおとなしい子や体を動かすのが苦手そうな子供は少ないことがわかりました。これは、子供の多くがアンケートに積極的に答えてくれたことや、未知の遊びに対して興味を持ち、積極的に遊ぼうとしていたことから、そのように判断しました。このような観察結果になった理由として、公園に存在している遊具の殆どが、体を大きく動かす必要のある動的な遊びだからではないかと仮説を立てました。

### 3. コンセプトとフィードバック 
インクルーシブDayでのリサーチ結果を踏まえて、身体的な動きを最小限にしつつ、自分の感情を形にするワクワク感を楽しめる、静的で創造的な遊びを提案することとしました。より具体的には、『今の気持ち』を伝えると、その気持ちに応じたモンスターがキーホルダーとして出てくる体験型の遊びを提案することとしました。

#### 3.1 デモ映像
ユーザーが感情を入力するとAIが感情モンスターを作成し、キーホルダーとしてプレゼントされます。この時はパラメータを入力するためのインターフェースを作成していないため、感情シートにシールを貼って回答してもらい、私がターミナルから入力するという形式を取っていました。また、キーホルダーにするための穴開け処理と3Dプリンタの操作を自動化することが、時間的・技術的に困難だったため、手動で行うことを想定していました。そして、ユーザーが感情シートに回答してから3Dプリントが完了するまでの待ち時間には、3Dプリンタが造形する様子を眺めるのに加えて、カームダウン効果が見込めるような落ち着いた映像を見てもらう想定していました。この映像はループ再生されており、可変式の待機時間に対応しています。

#### 3.2 インクルーシブ性
- 簡単な入力操作のみで完結するため、身体的な制約をほとんど受けない
- 感情を言葉ではなく形で表現できる
- 動的な遊びが苦手なユーザーでも楽しむことができる

#### 3.3 ユーザーシナリオ
- **シナリオA : 感覚過敏を持つユーザー**
    - 騒がしい場所から離れて、映像を見てゆったりと楽しむ
- **シナリオB : 身体を動かすのが難しい、もしくは苦手なユーザー**
    - 身体をほとんど動かさず、モンスターが出来上がるまでを楽しむ
- **シナリオC : 言語化が苦手なユーザー**
    - 自分の気持ちを言葉ではなく、形として表現して楽しむ

### 4. Micro Maker Faire Kyoto 2026
#### 4.1 ブラッシュアップ
Micro Maker Faire Kyoto 2026に、研究室(厳密には「京都産業大学ファブスペース」)として出展できることになりました。そこで、インクルーシブDay 4th やシンポジウムでのフィードバックを踏まえて、いくつかの改善を行いました。改善した点は大きく二つあります。一つ目は、ユーザーが直接感情パラメータを入力できるように、インタフェースとなるアプリケーションを作ったことです。従来は、紙にシールを貼ってもらったのを確認して、私がターミナルから入力を行うというものでした。そして二つ目は、3Dモデルの生成で止まるのではなく、3Dプリントまでの工程を自動化できるパイプラインを組んだことです。こちらも、従来は3Dモデルが生成されBlenderでリサイズなどの後処理が行われた後には、私が手動でスライサーソフトに読み込んで3Dプリンタを動かす必要がありました。この二つの改善は、私のプロジェクトにおいてとても大きな意味を持つと考えます。それは、ユーザー自身の手によってほとんど全ての工程を完了することができるようになったという点です。これは例えるなら、ポップコーンを単に店員に頼むか、ポップコーンマシンを用いて自身の手で作りあげるかという違いに似ています。ユーザーが感情の入力から3Dプリントまでを行えるようになって初めて、それが単に独立した技術の集合ではなく、一つの体験として昇華することができたのだと思っています。

感情の入力が完了すると、この画面に遷移します。この画面の裏では、Gemini API → Tripo API → Blender → PrusaSlicer → OctoPrint → 3D Printer までの連携が行われています。この画面では、5分程度の待機時間が発生しますが、ボトルネックとなっているのはBlenderでのホログラムレンダリングの工程です。次の3Dプリント待ち画面の中央にホログラム風のモンスターが表示されますが、その動画素材はこの工程で用意しています。フレーム数や解像度、デノイズを下げることで、より早くレンダリングが終わることが予想できますが、品質との兼ね合いである程度の待機時間が発生することは許容しています。

    <div className="image-stack">

この画面では、生成されたモンスターの360度回転アニメーションと、孵化予定時刻が表示されます。モンスターのアニメーションは先ほどの工程でレンダリングを行なったものを利用しているため、現在はどのようなモンスターが3Dプリンティングされているかを確認することができます。また、孵化予定時刻は、現在時刻に3Dプリンティングにかかる時間を加算したものに、さらに5分加算したものを表示しています。この予定時刻になれば、出来上がる瞬間を見届けることができます。

#### 4.5 展示の総評・反省点
Micro Maker Faire Kyoto 2026 では、想像の何倍も沢山の方が来場してくださり、私のプロジェクトにも多くの方が見学や体験をしてくださりました。これまでも何度かプロジェクトを紹介する機会はありましたが、実際に体験してもらうことは初めてであり、大勢の大人や子供に「面白そう」、「やってみたい」といった声を聞けたのは、このようなイベントならではと強く感じました。しかし、当日の私のプロジェクトはお世辞にも順風満帆とは言えず、多くの問題が発生しました。一つは、3Dプリント中にコンセントが抜けてしまい、3Dプリントが中断されてしまったこと。これは、コンセントを会場から借りたものを利用していたことが原因で、コンセントの大元が会場の中央にあったため、ふとしたことで抜けてしまうということが頻出していました。これは、研究室から持ってきていたバッテリーにコンセントを繋ぎかえることで解決しました。二つ目の問題は、Tripo APIがランタイムエラーを出力し、新しいモンスターの生成が不可能になってしまったことです。Tripo APIがランタイムエラーを出力することはテスト段階では起こらなかった問題で、とても致命的でした。対策として、ランタイムエラーを出力した場合には、すでにある3Dデータをパイプラインに載せることで、プロジェクトが全く体験できないということは防ぎましたが、感情に応じたモンスターが生成できるという体験を裏切ることになりました。これらの問題もあり、実際に体験してもらったユーザーは8人程度となり、もっと多くのユーザーに体験してもらえたはずの機会を逃したのは残念でした。総評すると、ハードウェアならではの難しさと、AIサービスをプロダクトに組み込むゆえの不安定さが大きく出た結果となりました。

このシェーダーは、大きく分けて二つのノードの組み合わせによって実現しています。一つはフレネルを用いたアウトラインの表示です。これによって、ホログラム特有の正面からは透過されるが、輪郭に近い部分だけが表示されるという特徴を表現しています。そして二つ目のキーとなるノードは、波テクスチャです。波テクスチャを用いることによって、下から上に上がってくるような波状のノイズを再現しています。フレネルを用いたアウトラインのみの表示と、波テクスチャを用いた波状のノイズを組み合わせて、ホログラム風シェーダーの実現を行なっています。
